# Code Quality Guide

이 문서는 React + TypeScript 작업에서 팀이 같은 기준으로 리뷰하기 위한 최소 규칙입니다.
목표는 멋진 추상화가 아니라 팀원이 빠르게 이해하고 안전하게 수정할 수 있는 코드입니다.

## Readability

- 페이지 컴포넌트는 화면 흐름이 위에서 아래로 읽히게 둡니다.
- 조건 분기와 UI가 복잡하게 섞이면 케이스 컴포넌트나 작은 하위 컴포넌트로 분리합니다.
- 긴 조건식, 매직 넘버, 반복되는 문구에는 이름을 붙입니다.
- helper 함수는 핵심 플로우를 가리지 않도록 파일 하단이나 별도 파일로 분리합니다.
- 중첩 삼항 연산자는 피하고 명확한 변수나 조건 렌더링으로 풉니다.

## Predictability

- 같은 이름은 같은 동작을 해야 합니다.
- `useXxxQuery` 계열은 TanStack Query의 반환 흐름을 크게 숨기지 않습니다.
- API 함수는 원본 서버 응답을 가져오는 책임, 정규화 함수는 화면 타입으로 변환하는 책임을 분리합니다.
- 함수 이름에 드러나지 않는 storage write, navigation, analytics 같은 부수효과를 숨기지 않습니다.
- 실패 가능성이 있는 로직은 빈 값, 로딩, 에러 상태를 호출부가 판단할 수 있게 만듭니다.

## Cohesion

- 함께 바뀌는 코드는 가까이 둡니다.
- 기능 단위가 커지면 `features/<domain>/` 구조를 우선 검토합니다.
- API 타입, API 요청 함수, 화면 전용 타입의 책임을 섞지 않습니다.
- UI 문구, 기본 page size, sort key처럼 같이 바뀌는 값은 상수로 모읍니다.

## Coupling

- 여러 화면에서 쓸지 확실하지 않은 컴포넌트는 섣불리 공통화하지 않습니다.
- 공통화 때문에 파일을 계속 오가야 한다면 중복을 허용합니다.
- props가 3단계 이상 깊게 내려가면 composition, context, store 중 하나가 필요한지 검토합니다.
- 컴포넌트가 API 원본 필드명에 직접 의존하지 않게 합니다.

## Frontend Defaults

- 사용자에게 보이는 문구는 한국어로 작성합니다.
- 누락 데이터는 요구사항 기준에 맞춰 `N/A` 또는 빈 상태로 표시합니다.
- 이미지에는 대체 텍스트를 둡니다.
- 버튼은 로딩/비활성 상태를 표현합니다.
- 카드 클릭 영역과 버튼 클릭 영역이 충돌하지 않도록 이벤트 경계를 분리합니다.

## PR Review Checklist

- 핵심 플로우가 위에서 아래로 읽히는가?
- API 불확실성이 한 곳에서 관리되는가?
- 로딩, 에러, 빈 상태가 있는가?
- 새 의존성이 정말 필요한가?
- 반응형에서 텍스트와 이미지가 깨지지 않는가?
- 변경 범위가 PR 목적과 맞는가?
